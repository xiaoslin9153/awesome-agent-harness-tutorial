# 翔实深入浅出写作方法论固化

## 目标

响应维护者对 C-01 样板的最终方向确认：内容要像成熟技术教材一样翔实、可以事无巨细地讲；文笔不要机械，要做到深入浅出。把这套要求从一次性反馈固化为写作基础设施。

## 范围

- 范围内：`tutorial/writing-pipeline.md`、`docs/skills/tutorial-tech-writing/SKILL.md`、B-004 执行状态和本会话记录。
- 范围外：立即重写 C-01 或其他公开章节；C-01 需要在下一会话按新方法补齐缺口。

## 诊断

v0.2 已经移除行数上限并加入深度契约，但仍保留三个会导致简略的倾向：

1. Polish 目标仍强调「压缩开头」和「删除没有信息量的过渡句」，容易被执行成删解释。
2. 「初学者路线用最少概念」缺少方法论，容易退化成只给结论。
3. 深度门禁检查反例和因果链，但没有规定关键机制应覆盖动机、参数环境、失败路径、恢复和取舍。

同时，中文规则中的「超过 30 字优先拆句」「初学者段落不超过 6 句」虽然不是行数限制，仍可能让作者为了形式而切断因果。

## 决策

### 方法论一：问题清单展开法（Draft）

Draft 对每个机制追问七件事：解决什么矛盾、正常数据流、输入与环境差异、失败时哪些状态损坏、常见实现为何出错、三家如何解决、何时变差。缺失的问题必须能说明原因，不允许以篇幅为由跳过关键分支。

### 方法论二：详实展开九层（Skill）

核心机制按「问题 → 直觉 → 定义 → 正常路径 → 参数与环境 → 失败路径 → 常见误解 → 真实实现 → 取舍」检查。九层可以融入段落，不必各占一节，但不能静默消失。

### 方法论三：深入浅出三层（Pipeline + Skill）

每个抽象概念按「一句话直觉 → 精确机制 → 边界与反例」展开。禁止停留在类比当结论，也禁止跳过直觉直接罗列类型定义。

### 表达原则修订

1. 「翔实是默认目标，简洁是表达手段。」
2. 「深入浅出指表达方式，不是删减内容。」
3. 段落承担因果解释，列表承担枚举和对照。
4. 短句用于节奏，不为压缩切断中间环节。
5. 类比必须声明失效边界，然后回到字段、状态或调用链。
