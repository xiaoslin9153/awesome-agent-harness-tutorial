# M-06 审批模型 v0.3 重写

## 范围

## 旧稿审计

旧稿已有五种终态和请求投影原则，但缺少 learning_contract、核心不变量失效边界、8 个反例、完整因果链和第二张 Mermaid 图；框架对照仍是目录级 pending_review；没有核对 Reasonix fresh/auto-drain、DeepSeek Harness 四态 ask 映射、Pi immediate error result。

## 源码证据

1. Reasonix `aa82b2f`：
   - `internal/event/approval.go:5-67`：Approval 的 ID/Tool/Subject/RawInput/Fresh/Kind；WriteAccess directories/display/justification/PersistAllowed；Recovery failed/next/change/task grant 字段。
   - `internal/control/approval.go:18-58,60-91,284-332,547-552`：Approve 映射 allow_once/session/persistent 与 recovery action；approvalManager 是 leaf 且管理 ask/auto/yolo posture；fresh/requireHuman 不 auto-drain；WriteAccess 一律 fresh human；waitContext timeout。
   - `internal/control/controller.go:6116-6188`：pre-approved 前后双检、PermissionRequest hook deny 生效而 fresh 忽略 hook allow、emit ApprovalRequest、Notification、select timeout 后 cancel(id)。
2. DeepSeek Harness `b150a55`：
   - `packages/core/tools/src/index.ts:1678-1729`：serviceAsk 在无 approval/agent 时 degrade to deny；allowed-once/rejected/cancelled/unavailable 分别映射，cancelled 带 approvalCancelled。
   - `index.ts:1463-1503`：pre-execute waterfall/serviceAsk 后应用 decision/guard，caller+approval cancellation 转 aborted-before-dispatch，denial reason 成为 isError result。
   - `index.ts:1100-1128`：monotonic guard 可 deny 不可 force allow。
3. Pi `c49906e`：
   - `packages/agent/src/types.ts:56-69,97-107,270-277`：BeforeToolCallResult block/reason/terminate；context 提供 validated args；hook 在 validation 后执行并接收 abort signal。
   - `packages/agent/src/agent-loop.ts:600-668`：not found/validation/blocked/abort 都生成 immediate error result，保持 call/result 配对。
   - `coding-agent/src/core/extensions/types.ts:914-918,1087-1095`：ToolCallEvent input 可 mutate 且不再验证；ToolCallEventResult block/reason/terminate。

## 决策

1. 核心不变量定为未决即不执行、决策绑定请求、范围显式、fresh 不可自动放行、非授权终态可见、deny 可组合。
2. 明确 once/session/persistent/task grant/plan window 的失效条件。
3. 用 flowchart 表达 policy→request→四种非授权终态，用 sequence diagram 表达等待、取消和审计。
4. 新增反例覆盖工具名记忆、auto 吞 fresh、服务缺失默认允许、ID 错绑、hook 替人 allow、拒绝丢失、迟到 reply 和 session 切换旧卡。
5. 完整因果链采用 write_access 扩目录：Fresh 卡片、allow_once、mutation receipt、后续路径重新审批或拒绝观察。

## Polish

1. 统一 approval request、scope、fresh decision、auto-drain、approvalCancelled、fail-closed 和 monotonic denial 术语。
2. 装修许可类比只承担入门，随后给出字段契约、授权缓存失效和并发控制。
3. 设计取舍表补充 timeout fail closed 和 hook auto-allow 的适用条件。
4. 把沙箱兜底留给 M-07，把 retry 幂等留给 M-08。
